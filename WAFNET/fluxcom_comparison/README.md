# WAFNET x FLUXCOM comparison — side analysis

**This is not part of the FLUXNET Annual Paper 2026.** It is a standalone
comparison of West Africa Flux Network (WAFNET) eddy-covariance observations
against FLUXCOM gridded products, requested by Ossénatou Mamadou for the
WAF-Net paper. Requested via David Moore, 2026-10-14.

Everything for this analysis — code, data, figures, tables, and docs — lives
under this directory (`WAFNET/fluxcom_comparison/`). Nothing here reads from
or writes to the repo-root `R/`, `scripts/`, `outputs/`, `review/`, or `docs/`
directories used by the Annual Paper, with one deliberate exception: `code/`
reads (never writes) the existing repo-root `data/extracted/` YY/MM FLUXMET
extracts for these sites, which are already present from the Annual Paper's
own download of the same sites — see `docs/methods_memo.md` for the exact
read-only paths.

**FLUXCOM is non-Shuttle data.** Per `CLAUDE.md` Hard Rule #1, it may only be
used here as an explicitly-labelled comparison dataset — never as primary
data for the Annual Paper. Every script, table, and figure in this directory
must label FLUXCOM outputs as "comparison data (non-Shuttle)" and must never
feed into any Annual Paper output.

## Requested analyses

1. Scatter plots of observed EC fluxes vs. FLUXCOM, for GPP, Reco, NEE, H and
   LE, at monthly (primary) and annual (secondary, ≥3 overlapping years)
   scales.
2. Bias (product minus tower), RMSE and R² per site, plus a site map
   sized/coloured by bias.
3. Multi-site Taylor diagrams, monthly and annual.

VUT where the site has it and CUT otherwise (the same per-site rule as the
Annual Paper — see `R/site_annual_fluxes.R`) throughout. GPP/Reco
partitioning is **product-dependent**: Stage 1 defaulted to the daytime
partition (`GPP_DT`/`RECO_DT`, the WAF-Net paper's general preference — a
deliberate exception to the WUE pilot's ban on daytime partitioning, which
does not apply to this analysis); Stage 2's FLUXCOM-X-BASE comparison uses
the **nighttime** partition (`GPP_NT`/`RECO_NT`) instead, because X-BASE's
own GPP training is nighttime-only (see `docs/report_back_2026-11-03.md`
section 3) — both partitions' QC-overlap rows are kept in
`tables/site_variable_qc_overlap_{yy,mm}.csv` for whichever product a given
comparison needs. H and measured respiration cannot be compared against
FLUXCOM-X-BASE at all (section 4 of the same report).

## Status

**Stage 1 — pre-analysis report only** (`docs/report_back_20261014.md`): no
gridded FLUXCOM products downloaded, no comparison statistics computed.
FLUXCOM product survey, training-site membership, observation QC/overlap,
grid-scale/land-cover context, and the decisions Stage 2 needed to resolve.

**Stage 2 — FLUXCOM-X-BASE download and comparison, done**
(`docs/report_back_2026-11-03.md`): the originally-chosen product (original
FLUXCOM RS+METEO) became unobtainable, so Dave switched to FLUXCOM-X-BASE
(Nelson et al. 2024, ICOS Carbon Portal, CC BY 4.0, 2001–2021) and kept the
original as an option if it resurfaces (a documentation-only ILAMB backup
copy of it is on disk, unused in the comparison). Downloaded (84 files,
sha256-verified), training-site list confirmed directly from the paper's own
Table 1, GPP/RECO matched to X-BASE's nighttime-only partitioning, RECO
derived (GPP + NEE), ET converted to LE, monthly bias/RMSE/R² computed per
site × flux (annual as a secondary look where ≥ 3 years overlap), and draft
scatter/map/Taylor-diagram figures produced — see the report for the full
numbers, every unit conversion, and what X-BASE cannot compare (H, measured
respiration). `docs/methods_memo.md` has the running log of filtering and
derivation decisions. Pending Ossénatou's sign-off: whether to formally add
`SN-Nkr` to the agreed site set now that it has FLUXCOM-X-BASE overlap.

**Stage 2 fixes and climatology figures, done** (`docs/report_back_2026-11-03.md`
section 8): a wording error (RECO's derivation was mis-stated in the report
as "GPP minus NEE"; the code always computed GPP + NEE) and three figure
issues (inconsistent site colours across figures, overlapping site-map
symbols at `BJ-Nhu`/`BJ-Bfg` and `SN-Dhr`/`SN-Nkr`, and a clipped Taylor
diagram reference label) were found and fixed. New: one mean-seasonal-cycle
(climatology) figure per site, tower vs. X-BASE by calendar month, built from
the exact site-months used in the Stage 2 statistics
(`figures/draft_climatology_<site>.png`, `tables/xbase_climatology.csv`) —
X-BASE's seasonal amplitude is smaller than the tower's at every site and
flux checked, most severely at `ML-Kem`.
