## What went wrong, and was fixed, during this build

- **Early silent script failures (both figures)**: `nohup ... &`-style background launches of
  `scripts/figure4_representativeness.R` appeared to exit in ~5 seconds with no output and no
  error. Root cause: the script `sink()`s its own stdout/message stream to a fresh, internally
  timestamped `logs/figure4_representativeness_<timestamp>.log` partway through (a pre-existing
  mechanism, not something this task introduced) — my shell-level log redirect only ever
  captured the few lines printed before that `sink()` call. The script was actually running (and
  completing) correctly the whole time; its own internal log file had the real output. No code
  change was needed, just reading the right log file.
- **Sampling-ratio verification false mismatch (Figure 7)**: the first poster render warned that
  neither panel exactly matched `supplementary_data_2_sampling_ratios.csv`. Diagnosed by direct
  inspection of the CSV: for a "none" class (zero towers, e.g. Köppen `EF`, Aridity
  `Hyper-Arid`), the CSV stores a literal `sampling_ratio = 0`, while `build_panel_df()`'s own
  `sampling_ratio` column (used by the figure's drawing logic, specifically to trigger the
  dashed "none" bar rendering) is `NA` for the same rows — two valid representations of the same
  "zero towers" fact from different code paths, not a data discrepancy. Fixed by re-deriving the
  comparison ratio as `tower_share / land_share` directly (without the NA-guard) in the
  verification step only — the figure's own drawing logic, which needs to distinguish "none"
  from "really is zero", was not touched. Re-ran; both panels now match exactly (see above).
- **Figure 7 width (11in) clipped titles and collided in-bar labels/the bottom caption**: the
  first full-size render at the task's literal "about 11in wide" clipped the panel title text
  at the right edge and overlapped the "% land" value with the clip-ratio annotation on the
  "Desert (BW)" row, and overlapped the "smaller proportion"/"greater proportion" caption text
  with itself. Root cause: this script's row/column geometry is calibrated for the manuscript's
  own 91.5mm single-panel column width at 7pt text; scaling text ×4.6 without scaling the
  column width by the same factor shrinks the bar/label area's *share* of the column (text
  scaled ~4.6×, an 11in column only ~3.05× the paper's 91.5mm), which is what crowded and
  overlapped. Fixed by scaling the column width by the same factor the existing
  `FLUXNET_PRESENTATION_MODE` block already uses for this exact script's own slides
  (`COL_WIDTH_MM <- 91.5 * k`) — reusing a mechanism already proven in this file, not a new
  guess. **Result: Figure 7 is 16.57in wide, not "about 11in."** This was a deliberate trade-off
  against the task's own "nothing overlaps" and point-size-floor requirements, which take
  priority over the approximate ("about") target dimensions — the same floor-over-box-size
  priority this script's own `FLUXNET_PRESENTATION_MODE` block already documents and applies
  for an analogous reason (see its `k_fit`/`K_FLOOR` comment).
- **Figure 7 height (22.22in, not "about 16in")**: with 21 total class rows (14 in the
  Köppen-Geiger panel including its header row, 7 in Aridity) at the text size needed to clear
  the stated 32pt axis-title minimum, the figure's content genuinely needs about 22in of
  vertical space at a row pitch scaled proportionally to the text (shrinking the row pitch
  disproportionately to the text risks exactly the kind of vertical crowding found and fixed
  above). Reported rather than forced to fit, for the same reason as the width.
- **`draw_panel2()`'s line weights could not be scaled from outside the function**: unlike
  Figure 2's panels (built via `R/figures/fig_network_growth.R` functions that take a `line_pt`
  parameter, scaled after the fact with the new `agu_poster_scale_ggplot()`), Figure 7's panel
  renderer (`draw_panel2()`, defined inline in `scripts/figure4_representativeness.R`) has every
  line weight hardcoded as `nature_lwd(<fixed number>)` in its body. Added a new `lwd_scale = 1`
  parameter (default preserves current behaviour exactly) rather than hand-rolling a separate
  poster-only panel renderer — confirmed default-preserving by rerunning the manuscript's own
  render (`FLUXNET_POSTER_MODE` unset) after this change and diffing
  `review/figures/representativeness/fig_04_representativeness.png` (and the Geo-vs-Geo
  companion) against their pre-change committed bytes: identical (only each run's PDF/meta.json
  timestamp differs, as it would on any rerun regardless of this task — restored both, see
  below).
- **Every full run of `scripts/figure4_representativeness.R` writes its own output straight
  into `review/figures/draft_manuscript_v1/`** (`fig_07_network_sampling.*`,
  `figS7_sampling_gridded_at_tower.*`), not just into its own `review/figures/
  representativeness/` working directory as I first assumed from `scripts/
  build_draft_manuscript_v1.R`'s comments (which only say Figure 4 isn't sourced *from that
  other script* — this script copies its own output directly, every run, by design). Content
  (PNG) came back byte-identical on every rerun (confirmed); only each run's PDF/`.meta.json`
  timestamp differed, as would happen on any rerun of this script regardless of this task.
  Restored all of `review/figures/draft_manuscript_v1/` and `review/figures/representativeness/`
  (`git checkout --`) after every rerun. Also restored `outputs/session_info.txt` and the
  `data/snapshots/*.meta.json` companion files the script's own earlier phases touch on every
  run (same timestamp-only diffs) — left untouched by this task's own debugging cycle.
- **Three generated `.legend.txt` lines had line breaks instead of inline values**: a vector
  passed to `writeLines()` with bare numeric/variable elements not wrapped in `paste0()` puts
  each element on its own line. Fixed in both scripts (wrapped in `paste0()`); confirmed in the
  regenerated `.legend.txt` files above.
